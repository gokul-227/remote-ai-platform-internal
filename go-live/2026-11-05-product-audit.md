## Backend fixes made in this phase

1. **Channel retry-token scope:** an author's retry token is globally unique. Previously, submitting it in another accessible channel returned the old message even when access to the original channel had been revoked. Both ordinary retry and concurrent uniqueness recovery now reject a channel mismatch with 409 and never return content from another channel. Same-channel retries remain idempotent.
2. **Assistant task access:** historical task assignment no longer grants read access after project membership removal. The query requires current membership, owning company, or staff permission and excludes deleted projects.
3. **Cross-project task list:** `/projects/my-tasks` applies current project membership/ownership rather than exposing task/project/latest-submission metadata solely by historical assignment.
4. **Assistant group access:** `my_groups` excludes pending and banned memberships.
5. **Document revision concurrency:** saves and restores now acquire `SELECT FOR UPDATE` and refresh cached state before checking/incrementing versions, serializing revision creation on PostgreSQL. Added two real-PostgreSQL regressions for save conflicts and simultaneous restores.
6. **Channel composite cursors:** history/polling accept paired `before`/`before_id` or `after`/`after_id`, retaining the existing list response and timestamp-only compatibility. Database comparisons use both timestamp and id so equal-timestamp pages do not drop messages. Tests cover backward and forward walks smaller than the tied-message batch.
7. **Safe website viewing:** `/browser/views` and historical `/browser/view` are retired with 410. No third-party HTML is fetched, rewritten, or stripped of frame restrictions by these routes. Unauthorized view-creation requests still return 401. The frontend is being updated by the coordinating agent to direct viewing.

No schema migration or paid service is introduced. Changes are uncommitted and local until coordinated review/release. Rollback through the normal feature-branch process; do not re-enable the unsafe proxy for launch.

## Remaining release requirements and limitations

- **Deployment provenance:** production frontend and actual API both currently report baseline SHA `1df5b24` and the API readiness check is healthy (runtime-agent evidence). The changes in this branch are not deployed. Deployed frontend/backend SHA and authenticated critical journeys must match the tested release before promotion is complete.
- **Production migration compatibility:** local PostgreSQL evidence now covers all 55 migrations from empty and all ten concurrency tests. Production schema version, a current backup and compatibility with existing live data remain to be verified; fresh-database migration success does not prove live-data safety.
- **Meeting reliability:** STUN-only WebRTC has no reliable fallback through restrictive networks. Do not advertise general-purpose Zoom-equivalent calling. Verify external-link and/or native calling boundaries and show explicit failures.
- **Channel client integration:** composite cursor backend and regression tests now pass; verify the updated client sends both timestamp/id edge values during polling and older-page fetch in browser journeys.
- **Operator/legal identity:** real operator/privacy/terms details must be supplied and validated by the owner; no identity or compliance claim may be invented.
- **Auth/provider configuration:** real Supabase sign-in/refresh, social providers, private resume/object storage, GitHub callback/revocation, email deliverability and AI quota/outage behavior need current environment evidence.
- **Recovery:** demonstrate a current backup restore and release rollback against the deployed schema; scripts alone are not recovery proof.
- **SEO scope:** only genuinely public, consented content may be indexed. Account settings, private messages, contract details, private project/documents and staff tools must remain private. Search eligibility and rankings are not guarantees.
- **Job source policy and reconciliation:** adapters require explicit source-specific display/republication permission and accurate attribution; a public endpoint alone does not establish a license. See the parallel ingestion audit for current per-source gates. Time-based unseen expiry is a freshness policy, not verified employer closure. Full closed-job reconciliation remains a limitation. External upserts also retain some previously recorded job-type/experience/currency/salary fields when a source changes or removes them; agree and test compensation freshness semantics before treating those fields as continuously current.
- **Feature breadth:** the platform implements coherent bounded workflows inspired by these products; it does not implement every feature of all reference products. Office fidelity, enterprise chat/media scale, browser-engine privacy, competitor recommendation algorithms and payments are not established.
